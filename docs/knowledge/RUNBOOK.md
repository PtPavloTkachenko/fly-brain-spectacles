# Runbook

`$REPO` = this repo's clone; `$CYBERFLY_RUNTIME` = runtime folder (default `~/cyberfly_runtime`, ADR 25).

## Setup brain runtime (once)
```sh
scripts/setup_mac.sh              # idempotent: prerequisites, fly-wirehead pinned at fcefe94, uv sync, prepare
DRY_RUN=1 scripts/setup_mac.sh    # checks only
# manual equivalent:
git clone https://github.com/mattyhempstead/fly-wirehead "$CYBERFLY_RUNTIME/fly-wirehead" && cd "$CYBERFLY_RUNTIME/fly-wirehead"
git checkout fcefe94 && uv sync && uv run flywirehead prepare   # ~1.1 GB MaleCNS, SHA-256 verified; re-run = verify only
```

## Run project scripts against the runtime
```sh
cd "$CYBERFLY_RUNTIME/fly-wirehead"
uv run python "$REPO/brain/discover.py"
uv run python "$REPO/brain/instincts.py"
```

## Run the brain server + verify without the lens
```sh
scripts/run_server.sh             # live config: --flies 3 --cloud 16000 --engine batch --kernel metal (ADR 18/23)
                                  # log: $CYBERFLY_RUNTIME/logs/brain_server_<date>.log
METAL=0 scripts/run_server.sh     # CPU kernel (--kernel fast); `--engine process` = old per-fly processes
BG=1 scripts/run_server.sh        # background (prints PID); extra flags pass through, e.g. --flies 1
DRY_RUN=1 scripts/run_server.sh   # print the command only. It is:
# cd "$CYBERFLY_RUNTIME/fly-wirehead" && uv run --with websockets --with zeroconf python "$REPO/brain_server/server.py" \
#   --flies 3 --cloud 16000 --engine batch --kernel metal
# wait for 3 × "ready baseline" (~4 s; first run also compiles the kernels), lens rows log as `LENS sel=… step=…ms cloud=[…] scan=[…]`; then:
cd "$CYBERFLY_RUNTIME/fly-wirehead" && uv run --with websockets python "$REPO/brain_server/fake_lens.py" --fly 0 --secs 5
dscacheutil -q host -a name flybrain.local      # mDNS check
pkill -f "brain_server/server.py"               # stop
```
Healthy fake_lens (2026-09-11, 5 brains): motion_left/right turn −0.92/+1.00 · food_left/right orient −1/+1 · loom_left/right escape_L/R 1.0 · sweet feed 0.97 · bitter stop 1.0, feed 0.

| Symptom | Cause | Fix |
|---|---|---|
| `zsh: == not found` in shell scripts | zsh expands `=word` | quote separators: `echo '==='` |
| Brain "slow" (~7× below real time) | per-delivery random access to ~8 separate per-neuron arrays (not the connectome copy, not bandwidth) | `scripts/run_server.sh` = `--engine batch --kernel metal` (GPU, exact, ADR 23: 3 flies ≈ 120 ms/step live); CPU: `--kernel fast` = 2× at 3–5 flies, bit-identical (ADR 21); one fly on idle cores: `--kernel par3` 2.8×. | MCP `SetLensStudioProperty` returns "set to {}" and nothing changes | LS 5.15 MCP doesn't parse `vec3`/`transform` object values | set scalar components: `localTransform.position.z` with `valueType: number` |
| MCP `lens-studio` ConnectionRefused after LS restart | each LS launch picks its own MCP port (was 50041, now 50051) | update the `lens-studio` user entry to the new port, then `/mcp` → Reconnect |
| 8 brains in parallel only 2.6× faster than 1 | shared caches: every process randomly touches ~8 per-neuron arrays per delivery (8.6 s per 500 ms in each of 8 workers vs 3.4 s alone); sharing one connectome copy does NOT help (measured 1.0×) | process engine: 5 flies ≈ 0.064× real time each (783 ms/step under load); batch+fast ≈ 0.14× (354 ms) — see ADR 21 / `engine/RESULTS.md` |
| Segfault in a multi-threaded native kernel called via ctypes | a `thread_local` named inside a lambda that runs on a spawned `std::thread` resolves to THAT thread's (empty) instance, not the caller's | bind a plain pointer before spawning (`Local* LS = locals.data()`), as in `engine/kernel_batch.cpp` |
