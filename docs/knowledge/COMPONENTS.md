# Components & contracts

## Fly brain (fly-wirehead core, MaleCNS v1.0)
- 166,700 neurons, 25.6 M edges, LIF at dt 0.1 ms (Shiu 2024 params: rest −52, threshold −45, τm 20 ms, τsyn 5 ms, delay 1.8 ms, refractory 2.2 ms, weight = contacts × 0.275 mV, sign from transmitter).
- API: `VisualMemoryBrain().rgb_step(frame_rgb_uint8, ms≤10, learning=False, stimulation=[(indices, mV)])` → spike counts per neuron. `reset()` restores initial state + weights. Deterministic (no noise).
- Cell lookup: `annotations(brain.ids)` columns `type`, `somaSide`, `rootSide` (use `rootSide` for sensory neurons — their `somaSide` is empty).

## Brain server (`brain_server/`) — contract
- `server.py`: N worker processes (one MaleCNS brain each, `worker.py`), one WebSocket `:8790`, mDNS `flybrain.local`. JSON frames with `t` (`protocol.py`, `decode_many` for LS-merged frames). Broadcasts to all clients.
- `--engine batch` (off by default): all flies in ONE process (`engine/batch_worker.py`), one shared connectome, one thread per fly running the same `worker.fly_loop`. `--kernel orig|fast|par2|par3`: `fast` = same arithmetic with packed per-neuron state; `parN` = each fly on N threads. All bit-identical to the process path (`engine/test_equality.py` spikes + full state, `engine/test_contract.py` messages). Numbers: `engine/RESULTS.md`. `--kernel metal` = the same kernel on the Apple GPU, all flies in one command buffer per 10 ms chunk. It gives the same spikes, and the fly's state fields are numpy views on Metal buffers. Frozen weights only (`engine/metal/RESULTS.md`, `engine/metal/test_metal.py`).
- **Page -> lens commands (ADR 68)**, event `cmd` on the relay socket, `WebBrainLink.onCommand` -> `FlySwarm.pageCommand` -> `FlyTrainer.command()`: `{t:"cmd", cmd:"train", mode:"food|danger|forget|test|choice|transfer", cs:"<label>", csMinus?:"<label>", bouts?:N}` · `{t:"cmd", cmd:"train_stop"}` · `{t:"cmd", cmd:"reset"}` (FlyMemory.reset) · `{t:"cmd", cmd:"memory_set", data:"<b64>"}` (installed as the lens's canonical copy + saved). Lens -> page in the scene feed, each only when it changes: `train` (TrainState), `train_summary` ({pack, verdict}), `things` (the exact labels a `cmd` cue is matched against), `mem.key` (the versions-table row id, never displayed). **Teaching is refused unless a page is the brain** (`FlyTrainer.available()`, `TRAIN_WEB_ONLY`); the key stays visible and says why.
- **FlyVerdict** (`FlyVerdict.ts`, ADR 68): `askVerdict(pack, cb)` -> `{learned, confidence, what, evidence[], caveats[], next[], plain, via}` through the RSG Gemini path, schema-constrained, with a prompt that forbids inventing a number, requires the control to be named, and carries the null rule. `localVerdict(pack)` states the numbers flatly when Gemini is unreachable; `via` always says which ran.
- Learning readouts (ADR 67): `memory.eff_on` / `n_on` = the efficacy of ONLY the plastic synapses whose presynaptic Kenyon cell fired this step — the cue-specific memory `mean_efficacy` hides. `{"kc_inh_gain": g}` scales the 4,633 APL->KC synapses (default **1.0 = the file exactly**, verified identical; higher = a sparser odour code, and measurably WORSE learning — ADR 67). Readout `APL` (2 cells, 5 Hz at rest, ~287 Hz under odour).
- Odour identity (ADR 65, widened to sixteen in ADR 105): besides the generic `odor`, a source drives ONE of `odor_va2|dm4|dm2|dm1|dm3|dl5|dc1|vm2|va6|dc2|dl1|vl2a|vm1|dm5|vm7d|va7l` (its `Source.odourId`, hashed from the label) at `ODOUR_ID_GAIN`; each is one glomerulus with a nameable odorant (table in ADR 105). The channel exists only in `brain_c0_od16.flyb` and later, and on the Mac batch server from its next restart; the lens sends only what `FlyConfig.ODOUR_IDS` lists. Readouts `MBON07` (4 cells) and `MBON11` (2) carry the memory's output; they exist only in a brain file exported after 15.09 (`brain_*_mbon.flyb`), and `FlyTrainer` prints `-` when they are missing. Gotcha: the glomeruli separate structurally but NOT functionally (Jaccard 0.92-0.95 of firing KCs) — see ADR 65 before building anything on cue identity. ADR 93: a plain `object` now smells on its own — Gemini's `smell` 0..1 x `ODOR.object` (0.6, 35-70 cm) — into its identity glomerulus ONLY (never the generic `odor`, never hunger, never `forage`). ADR 94: the four were the EXPORT's ceiling (verified in the `.flyb` records), not the brain's 53 glomeruli; ADR 105 re-exported with sixteen — a wider set is the same recipe (RUNBOOK "re-export after channels.py changes").
- Lens → Mac: `hello{role,proto}`, `senses{fly, ch}`, `select{fly}` (brain-cloud stream), `pulse{fly, kind: reward|punish}` (200 ms), `reset{fly}`, `ping{ts}`.
- Mac → Lens: `welcome{proto, flies, cloud}`, `ready{fly, baseline, channels}`, `brain{fly, sim_ms, wall_ms, act, neural, hz, cloud?}`, `pong`, `dead{fly}`.
- `ch` channels (`channels.py` SENSES; value 0..1, or `{L,R}` for sided ones): `light`, `loom`, `loom_wall`, `object`, `motion`, `odor`, `odor_<g>` x16 (ADR 105), `odor_bad`, `wind`, `touch`, `bristle`, `ocelli`, `haltere` (sided) · `sound`, `sweet`, `bitter`, `hot`, `cold`, `dry`, `moist`, `hunger`, `reward`, `punish` (global). 1.0 = 20 mV into those cell types. A key the brain file lacks is skipped silently.
- `act`: `steer` (−1 left … +1 right; = DNa02 turn + DNp66 orient, deadzoned), `turn`, `orient`, `escape_L/R`, `stop`, `back`, `feed`, `appetite`, `forward` (engineered, disclosed). `neural`: `arousal_hz`, `reward_hz`, `stress_hz`, `fear`, `appetite`, `feeding`, `attention`, `spikes`.
- `cloud`: base64 bitset over the fixed 16,384-neuron sample in `brain/results/cloud_subset.npz` (idx/xyz/superclass — the lens hologram uses the same file); ~11% lit per step. Only for the `select`ed fly.
- Habituation: `worker.py` BASE_TAU_STEPS=60 — the decoder baseline follows slow network drift (else flies got stuck at stop 1.0 / back 0.7 after minutes); sustained stimuli fade on ~30 s wall.
- Timing: each brain steps 50 ms neural per message; process engine ~0.4 s wall with 1 fly, ~0.6–0.8 s with 3–5; `--engine batch --kernel fast` ~0.33–0.35 s with 3–5 (ADR 21); `--kernel metal` (live) ≈ 0.12 s with 3 (ADR 23). Startup: 5 brains ready in ~11 s (800 ms settle + 500 ms baseline at REST_LIGHT 160/255, ADR 15).

## Perf probe and draw budget (ADR 69, 15.09)
- **The probe.** `FlySwarm.timed(name, fn)` and `FlyBoard.mark(k, t0)` measure with **`getRealTimeNanos()`** (StudioLib, monotonic ns). Never `Date.now()` (1 ms — coarser than every subsystem in this lens) and never `getTime()` (the frame clock; it does not advance inside a frame). Everything is float ms.
- **The row.** `perf ours=<worst>/<mean> <name>=<worst>/<mean> … | <name>=<worst> …`. Before the `|`: the top 8 subsystems by MEAN (steady cost — ADR 45). After it: keys that only carry a worst — `msg` (WebSocket parse, outside the tick) and the board's sections `b.top`, `b.cloud`, `b.bars`, `b.flush`, `b.mini`, `b.follow`. `ours` is the WHOLE `UpdateEvent`, so the listed subsystems must sum to slightly less than it; the gap is the untimed part of the tick.
- **Shape of the lens.** ONE `UpdateEvent` (FlySwarm) and one `OnStartEvent`; every other class is a plain object ticked from inside it. Any subsystem above ~1 ms is therefore a hard frame-rate ceiling.
- **Preview baseline (LS 5.23.2, `auto_solo`, 1 fly, board visible, M1 Max also running the brain server).** `ours` **1.37-1.46 ms/frame**; `Scene::Update` 1.76; `RenderFrame` 0.65; `Scene::LateUpdate` 0.14; `PhysicsUpdate` 0.06. `ProcessFrame`/`Track` (10.4 ms) is the PREVIEW's tracking simulation and is not a lens cost.

## Sense injection contract (input audit 11.09)
- **The floor.**
  - A channel value v means 20 mV × v into every cell of its types (`channels.py` `build_stim`, clipped at 1.5).
  - Cells fire only above about 7 mV (v ≈ 0.35) and saturate by about 0.5, so graded cues start at `SENSE_FLOOR` 0.45.
  - A 1 mV null poke already moves DNa02 ±12 Hz: smaller effects are noise.
- **Weak or inert in this model:**
  - sound (JO-A/B): no response;
  - the retina frame (photoreceptors saturate: context only, no information);
  - odour on ORN DM1/DM2/DM4/VA2 (appetite never rises).
- **Candidate senses that do move the brain (offline sims):**
  - halteres (power MNs −32 Hz);
  - ventral flow via VS (stop 0.61);
  - TPMN proboscis contact (feed +70 Hz);
  - ocelli OCG (turn 0.81, needs a repeat).
- **Readout facts:**
  - MDN `back` is driven by the object channel (LC10), not odour.
  - An attractive object lowers the power MNs 12–14 Hz, so thrust uses approach drive (ADR 30).
  - DNp03 is a clean same-side loom cell (+214 Hz). DNb01 has no side information. VES041 is tonic and rises during fixation.
- **Tools:** the audit sims (`sim_food.py`, `dose.py`) replay `worker.fly_loop` in-process for fixed sense dicts (CPU kernel, nice 15), without the server.

## Batched text (`TextBatch.ts`, `SdfTextLayout.ts`, `tools/text/build_atlas.py`) — contract (ADR 40)
- **Why it exists:** a `Component.Text` is its own mesh, its own draw call and a re-tessellation on every `.text` write. The board was 67 text draws of the ~90 in view; batched it is 28 and falling.
- **Atlas:** `python3 tools/text/build_atlas.py` bakes the project's own faces into `Fly/UI/Fonts/BoardUi.png` and `BoardMono.png` (RGB = 3-channel MSDF body, A = plain SDF outline, ASCII 0x20–0x7E, `-s 96 -p 8 -r 16`) plus `Scripts/Fly/Board*FontData.ts`. The TS module must not share a base name with the PNG or LS silently breaks `require()`.
- **Layout:** `SdfTextLayout.layout(text)` returns glyph rects in EM with atlas UVs. **Do not re-expand the quads by the distance range** — our atlas already carries `-p 8` padding and packs with `spacing [0,0]`, so expanding samples the neighbouring glyph (the labels render as smudges).
- **Batch:** `new TextBatch(parent, name, face, material, renderOrder)` → `begin()` / `add(text, x, y, z, capCm, color, align)` / `flush()`; `setRenderOrder(n)` after the fact; `drawnWidthOf(text, capCm)` is the real drawn width (`widthOf` under-measures by ~43 %). Its clone is `Add · depthWrite false · depthTest true · twoSided`, explicit (ADR 97). Colour rides in the vertices (uv2 = r,g, uv3 = b,a), so one batch holds every colour on the board. `flush()` hashes all items and skips an unchanged rebuild; the board's static labels are queued once in the constructor and never rebuilt.
- **Cap height** comes from the 'H' glyph MINUS `info.padding`; measuring the raw atlas rect makes every label ~20 % too small.
- **Assets:** the material resolves through `requireAsset`, a PNG does **not** ("Cannot find asset") — the atlas is bound on the material inside Lens Studio and the batch inherits it. If the generated `.mat` shows an empty `Properties` block, its PassInfo is dead: regenerate with a fresh PassInfo UUID (same Material UUID and Pass reference) and delete the `.meta`.
- **Blend:** additive. Normal darkens the plate at every glyph edge on the glasses.

## The shared brain core (`core/`, ADR 47, 52, 55, 87) — contract

**Not a device path.** ADR 87 deleted the in-lens brain, `NativeBrainLink` and `BrainLoad`. What is below is the core the **web page** (`web/build_wasm.sh` → WASM + WebGPU) and the **Mac server** (`--engine native`) share; nothing native runs on the glasses.
- **`core`** (C++, `flybrain.h`): `fb_create(bytes, len, step_ms, fly)` (FLYB or zlib FLYB), `fb_post(json)`, `fb_start/stop` (own thread, nice +10 on Linux), `fb_take(buf, cap)` (newest message), `fb_step/fb_warmup` (host loop), `fb_set_threads` (only from the brain thread's side: before `fb_start`, or via JSON). JSON in: `{"senses":{..}}`, `{"cloud":bool}`, `{"learning":bool}`, `{"threads":n}`, `{"duty":0.1..1}`, `{"pause":bool}`, `{"dt":x}` (before warm-up, experiments only), `{"pulse":"reward"|"punish"}` (reward = 20 mV into the 15 PAM11, punish = the 2 PPL101; both modulatory, so they move NOTHING except through the rule), `{"reset":true}`, and the memory commands of ADR 63: `{"memory":"get"[, "compact":true]}` / `{"memory":"set","data":"<base64>"[, "elapsed_s":X]}` / `{"memory":"clear"}` / `{"memory":"echo"}`. JSON out: the server's `brain` message (`act`, `hz`, `regions`, `neural`, `cloud`, `memory`, `wall_ms`, `prof.adv`) plus `dt`, `thr`, `duty`, `engine:"native"`. Gotcha: `wall_ms` is the step itself, never the duty sleep — that is what makes it the quota-squeeze signal.
- **Core memory (ADR 63)** — the plastic state as a portable blob. `fb_take` now reads a small never-dropped queue FIRST (memory replies) and only then the newest step message, so **no new module export was needed**. Out: `{"t":"memory","fly":0,"op":"get|set|clear|echo","ok":bool,"err"?,"edges","mean_efficacy","changed","rewards","punishes","sim_ms","bytes"?,"approx"? (set),"data"? (get)}`. The `brain` message's `memory{}` block gained `rewards`, `punishes`, `since_ms` (brain time since a weight last moved, -1 = never). Blob format `FMEM` v1 -> deflate (`FMEZ`) -> base64: 56-byte header (magic, version, flags, E, D, a fingerprint of the plastic edge set, stored-edge count, sim clock, age of the last change, the two US counters), u16 indices, then float64 arrays. **Sparse** (an edge whose KC never fired is exactly 0 and is not written) and **compact** (bit2/bit1 off = no `mem_w`, no 1 s traces: 10 bytes per moved synapse instead of 26 — exact for a brain that was switched off, because `mem_w`'s own contribution decays with tau 0.05 s and everything else about it is a function of `mem_u`). Gotchas: the fingerprint refuses a blob from a different brain file (`brain_c0` vs `brain_hot` renumber the neurons); `{"reset":true}` wipes the memory, `{"memory":"clear"}` does not touch the neural state; a `get` and a `set` posted as separate messages land one step apart, so the pair rewinds the rule by a step — use `echo` to prove the round trip.
- **GPU backend (`src/gpu/`, ADR 52 + **82**):** `brain.comp` (GLSL, six entry points; `tools/build_spv.sh` -> `brain_spv.h`, committed) + `vkbrain.{h,cpp}` (`vkbrain::Brain::create(Params)`, `run(steps, slot0)`, host-visible `cells()`, `edges()`, `queue(slot)`, `active()`, `set_drive/get_counts`, `set_units`, `set_acc`). Core side: `set_gpu(f)` (first use moves the CSR into the GPU buffer, one CPU thread from then on), `gpu_push/gpu_pull` (state hand-off at chunk boundaries), `gpu_chunk`, `gpu_check(k)`. JSON in: `{"gpu":0..1}`, `{"gpu_check":k}`, `{"acc":"plain"|"fma"}`; out: `gpu`, `gpu_on`, `gpu_ms`, `gpu_err`, `acc`, `gpu_check{ok,acc,wk,wexact,cells_diff,dv,dg,da,dlast,drefr,ulp,active_same,queue_same,spikes_cpu,spikes_gpu,cpu_ms,gpu_ms}`, ready `gpu:"<device>|off|<reason>"`, `acc`, `wk`, `wq`, `wexact`.
  - **Contract (ADR 82, `DETERMINISM.md`): the kernels agree by construction, not by reproducing each other's orders.** `evolve` (one `evolve_cell<FMA>` in `flybrain.cpp`, copied operation for operation into `brain.comp` / `brain.wgsl`) uses only `+`, `-`, `*`; the awkward constants live in the decay tables, built ONCE by `vkbrain::build_decay_tables` and shared through `Params::tab`. The synaptic weight is an integer (`Edge{i32 post, i32 units}`, `units = contacts x w_k`, `w_k` derived at load so no tick can overflow int32), so a tick's deliveries are summed with `atomicAdd` and enter `g` with one float rounding.
  - Gotchas: the kernel needs `MVK_CONFIG_FAST_MATH_ENABLED=0` on the Mac (set by `create`); a storage binding is capped at 128 MB on small GPUs (edges are bound in 2^23-edge slices). The old `rcap`/`scap` record limits are **gone** with the record buffer (-79 MB of GPU memory). Anything that changes `evolve_cell` must change both shaders and be re-checked with `{"gpu_check":20}`, not 3 — three chunks hid a real failure for a month.

## Boot card and the brain line (`FlyBoot.ts`, ADR 84, 87) — contract

- **`FlyBoot`** is the third card of the one flow (`FlyStart` → `FlyScan` → `FlyBoot` → the dashboard), a sibling of the board's content on the board root, built in `FlyBoard`'s constructor so every quad joins its batch before the first flush. **Three stages** (`STAGE_LABELS`): SESSION · THE ROOM · THE BRAIN. ADR 87 collapsed the card: the brain file, the unpacking and the GPU check were the in-lens core bringing itself up, and with no core they could only ever read SKIPPED — **nothing reads SKIPPED any more**.
- **Inputs.** `session(multi)` and `scanDone()` from `FlyBoard` (it already owns both events), `scan(seconds, found, surfaces)` from the same numbers the scan card gets, and `tick(dt, link, msg, linkOk, on)` every frame from `FlyBoard.update` — **before** the "is the board on screen" gate, so the stage clocks start with the lens's first frame. `on` drives the drawing only.
- **It reads, never writes.** Every stage comes from the structural `BrainLinkView` (`connected`, `status`, `webActive`, and the still-declared `isNative` / `gpuDevice` / `gpuLost` / `gpuCheck`) plus the arrival of a `BrainMsg`. `BrainLinkView.connected` exists so a plain `BrainLink` is assignable to it (a target of only-optional properties is otherwise rejected by TS's weak-type check).
- **Handover.** `done` = a `BrainMsg` arrived (plus a 0.9 s beat so the last row is read) or the wearer pressed `OPEN THE BOARD ANYWAY`. `FlyBoard.openDash()` is the only route to the dashboard; `FlyBoard.revealed` means "the scan is over", `FlyBoard.dashOn` means "the dashboard is up". Once `dashOn`, `FlyBoot` is never ticked again.
- **`FlyBoard` wiring from `FlySwarm`.** One line, once: `board.brainLink = this.link` (`FlySwarm.ts:317`). Without it the card still runs (SESSION and THE ROOM only) and the brain line falls back to "waiting for the brain" — it degrades, it does not break. **Dead input:** `FlyBoard.brainLoad` (`FlyBoard.ts:169`) is never assigned since ADR 87 deleted `BrainLoad`, so `brainWhy` / `brainNumbers` always get null for it.
- **Words, not numbers.** `brainWhere` / `brainStep` / `brainWhy` / `brainNumbers` are pure exported functions. Their load half (the "fps clamp: …" / "quota squeeze: …" wording of ADR 50) is inert now that nothing fills it; `brainNumbers` is the raw line and goes only to the "?" card (`FlyGuide.setBrainNumbers`).
- **Two traps this file already pays for.** (1) `tick` runs every frame from the lens's first, so every repeated line is a module constant — a string rebuilt per frame is the garbage ADR 39 rules out. (2) The card's text is batched MSDF (~0.26 cm/char at the 0.46 tier) but the board's brain strip is `Component.Text` (~0.9 cm/char at the same tier): a line that fits the card can be half again too wide on the strip. Keep `brainWhy`'s strings under ~44 characters, and `brainNumbers` under ~45.
